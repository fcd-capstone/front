# 백엔드 연동 협의 항목

현재 구현은 가상 데이터 기반입니다. 아래 내용은 프론트엔드의 제안이며 확정된 API 명세가 아닙니다.

## 필요한 데이터

| 기능        | 필요한 내용                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------- |
| 노드 현황   | 노드 ID, 설치 센서 목록, 연결 상태, 마지막 측정·수신 시각                                      |
| 최신 측정값 | 기획서 5.4절 필드, 모든 센서값 nullable, 원본/보정값 구분                                      |
| 시계열      | 노드·센서·시간 구간 필터, ts 정렬, 집계 간격, 결측 보존                                        |
| 이상 이벤트 | 고유 ID, 원인 코드, 대상 노드, 시작·종료 시각, 신뢰도, 판단 근거, 우선순위 점수·등급·산출 근거 |
| 조치 보고   | 이벤트 ID, 처리 상태, 메모, 저장 시각 및 저장 실패 응답                                        |
| 실험 라벨   | run, cause, start/end, ts, intensity, target_node, note                                        |
| 재생        | 사용 가능한 실험 파일/회차, 시작·정지·배속·시점 이동 지원 여부, 재생 시각과 세션 ID            |

## 합의할 규칙

1. HTTP 경로, 응답 예시, 오류 형식, CORS 및 개발 서버 주소
2. 폴링/SSE/WebSocket 중 실시간 전달 방식과 연결 복구 처리
3. 측정 주기 1초와 별개인 화면 갱신 주기·시계열 집계 전략
4. Unix 초 단위 시각과 한국 시간 표시, 서버 수신 시각과 화면 표시 시각의 구분
5. 미설치 센서와 일시적 결측·예열·연결 끊김의 구분 기준
6. 신뢰도 범위(0~1 또는 0~100), 저신뢰·복합/판별 불가 표현
7. 우선순위 점수 범위와 위험등급, 정렬·동점 처리
8. 원본값과 보정값의 제공 구조·표시 방식, 보정 적용 상태
9. 이벤트 시작·갱신·종료·조치 완료의 구분, 페이지네이션
10. 시연 재생 데이터와 실제 데이터가 섞이지 않게 하는 식별자

## 현재 목업과의 차이

현재 `SensorSource.read(cause, elapsed)`는 프론트 시연 전용 인터페이스입니다. 실제 API 주소나 재생 제어 계약을 의미하지 않습니다. 가상 이벤트 ID는 원인별로 고정되어 있고, 조치 상태는 시나리오 재생을 초기화해도 해당 브라우저에 남습니다. 운영 데이터 연동 시에는 서버 이벤트 ID와 서버 저장으로 교체합니다.
